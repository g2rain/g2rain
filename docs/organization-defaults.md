# G2rain 组织默认文档约定

本文定义新建或接入 G2rain 组织的仓库应具备的最小文档入口。它提供共同导航与职责边界，不替代各项目的实现、需求或运行手册。

## 默认文件

| 位置 | 目的 | 维护者 |
| --- | --- | --- |
| `README.md` | 面向使用者的项目定位、入口、环境、常用操作与安全提示 | 项目维护者 |
| `AGENTS.md` | 面向 AI 协作和 Review 的执行入口、读取顺序与不可逾越边界 | 项目维护者 |
| `docs/project.yaml` | 机器可读的仓库角色、采用基线、验证状态、命令与文档入口 | 项目维护者 |
| `docs/index.md` | 项目文档导航 | 项目维护者 |
| `docs/architecture/` | 本地架构、模块、依赖、运行流程与已登记偏差 | 项目维护者 |
| `docs/development/` | 本地开发、测试与完成定义 | 项目维护者 |
| `docs/operations/` | 配置、部署、发布、排障或恢复；仅适用于实际需要运行的仓库 | 项目维护者 |
| `docs/security/` | 信任边界、敏感数据处理与安全验证要求 | 项目维护者 |
| `docs/requirements/` | 当前与历史需求的入口；开发前必须能唯一确定活动需求 | 项目维护者 |

工具、库、模板、纯文档或计划中的仓库可以省略不适用的目录，但必须在 `docs/project.yaml` 说明其运行与验证状态。没有实现、构建定义或测试时，应明确标记为未验证，而不是推测命令或成果。

## 中央与项目事实的边界

中央 `g2rain/g2rain` 维护：

- 组织级术语、架构 Profile、跨项目 ADR、迁移规则与项目目录；
- 平台唯一服务、工具和共享库的跨仓库角色与契约；
- 架构治理、贡献、行为准则和漏洞披露规则。

项目仓库维护：

- 需求、领域设计、项目 ADR、代码、配置、部署、测试和项目级偏差；
- 实际的构建、运行、迁移和验证结果；
- 与中央基线不同但经批准的局部实现选择。

项目不得复制中央 Profile 后自行修改，也不得把本地配置、凭据或运行细节写入中央文档。项目文档需要通过固定基线引用、偏差文件和链接与中央资料建立关系。

## 何时更新中央资料

出现以下任一情况时，先在中央仓库提出或更新 ADR，再变更 Profile、目录或治理文档：

- 影响多个仓库的模块边界、依赖方向、数据所有权、安全模型或发布规则；
- 新增可复用的项目类别、正式 Profile、平台唯一服务、工具或共享库；
- 改变已发布 Profile 的兼容性或升级路径；
- 需要登记多个项目共同依赖的长期架构例外。

单个项目的需求、实现、环境配置、部署细节与短期局部偏差仍留在项目仓库。中央资料不能代替对源码、构建、配置和测试的验证。

## 文档变更检查

提交文档前至少检查：

1. `docs/project.yaml`、`docs/index.md`、Profile/目录引用和相对 Markdown 链接一致；
2. 事实陈述有代码、配置、测试、中央 ADR 或项目文档证据；
3. 不含凭据、私钥、Token、内部地址、个人数据或未公开安全细节；
4. `git diff --check` 通过；
5. 如果变更跨仓库，已说明 ADR、代表项目试点和后续显式基线升级要求。

组织级安全问题请遵循[安全与漏洞披露流程](../governance/security.md)；参与方式见[贡献指南](../community/CONTRIBUTING.md)和[行为准则](../community/CODE_OF_CONDUCT.md)。
