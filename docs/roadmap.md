# G2rain（谷雨）开源智能体平台路线图

**G2rain 已具备应用开发、部署与使用的基础，当前可以搭建平台环境、部署业务应用和知识库，智能体平台与智能客服已开发完成，待开放。**

路线图围绕六个方向展开：**基础搭建 → SaaS基座能力 → 知识库能力 → 智能体平台 → 智能客服 → 商业化**。这些方向逐层提供支撑，也可并行演进。后续工作以现有可部署能力为起点，持续完善场景、体验与运营。

更新日期：**2026-10-31**。具体项目配置和部署步骤由责任仓库维护；后续目标按需求与里程碑安排。

## 私有部署与云端运营

**私有部署场景已具备可用性。** 可以在企业自己的环境部署现有 SaaS基座、知识库和业务应用，按所选版本配置基础设施、模型与服务。智能体平台与智能客服已开发完成、待开放，其接入方式另行说明。

**计量计费属于云端运营建设，不是私有部署的可用性门槛。** 后续商业化中的交易、订阅、套餐、计量计费和账单用于支撑云端产品销售、租户开通与运营结算；这些规划不影响现有私有部署能力的使用。

## 二、SaaS基座能力

**当前状态：现有基座能力已可用。** 支撑业务应用接入，持续完善多租户使用场景。

**已可用能力：**

- **组织与租户**：以组织、部门、用户等主体组织业务归属和访问范围。
- **身份认证**：通过 IAM、SSO、会话与 Token 管理提供统一登录接入。
- **应用与能力开通**：围绕应用授权、控制域和控制单元组织租户可使用的能力。
- **岗位与资源权限**：连接角色、菜单、页面、按钮和 API，配合 Gateway 与领域服务执行校验。
- **平台管理与公共服务**：通过管理应用、字典、基础设施组件等支撑业务开发与日常维护。
- **应用承载**：通过主壳、子应用和网关组织多个业务应用的入口与协作。

**后续建设目标：** 完善租户开通、用户登录、应用接入、岗位授权到业务访问的完整操作指南；持续验证组织隔离、权限变更、会话失效与越权拒绝场景。

入口：[权限模型](permission-model.md) · [IAM 登记](architecture/platform-services/g2rain-iam.md) · [项目目录](architecture/catalog/projects.yaml)

## 三、知识库能力

**当前状态：已可用。** 知识服务与运营端 v1.0.0 已发布，可按项目文档部署使用。

**已可用能力：** 文件与 FAQ、分类与标签、主题与版本管理，以及审核、处理、发布、回滚、检索证据与回答接口。知识处理链路连接 Docling、Embedding、Milvus 与可选 Rerank；部署仓库提供对应业务扩展编排。

**后续建设目标：**

- 完善内容录入、处理结果查看、版本维护与发布操作体验。
- 围绕真实业务资料优化召回、排序、答案依据与引用展示。
- 完善问题反馈到知识修订、审核和重新发布的运营路径。
- 持续完善处理任务、失败重试、发布恢复与多实例运行能力。

**后续验收目标：** 使用者能完成“录入 → 审核 → 处理 → 发布 → 检索与回答 → 反馈修订”，并能核对有效知识版本与引用来源。

## 六、商业化

**适用场景：云端商业运营。私有部署使用现有能力无需等待本阶段完成。**

**当前状态：规划设计中。产品套餐、交易支付、自动开通、商业订阅、计量计费、账单对账与经营分析，均为待建设目标，尚未作为完整商业化能力交付。**

**已有可复用能力：** SaaS基座中的应用授权、租户能力开通与资源权限管理。

**待建设的商业链路：** 将订单、支付和订阅结果自动转换为租户权益与配额，并对使用行为计量、计费与出账。现有的应用授权和能力开通不代表已经具备交易支付、订阅或计费能力。

以下各小节均为规划设计内容，按产品需求分步实施。

### 产品与套餐

将应用、智能体、知识库和工具能力组织成可销售的产品，定义套餐版本、服务周期、使用范围、资源配额与价格。逐步支持试用、周期订阅、用量包和按量付费等模式，并明确套餐内额度、超额使用和有效期规则。

### 交易与开通

**选购产品 → 创建订单 → 支付确认 → 建立订阅 → 开通能力与配额 → 客户使用。**

| 方向 | 建设目标 |
| --- | --- |
| 商品与订单 | 记录购买租户、产品套餐、数量、周期、价格与交易状态，保留成交时的规则快照 |
| 支付与退款 | 处理支付结果、取消、超时与退款，关联订单和资金记录 |
| 自动开通 | 按有效交易或试用规则建立租户权益，连接 SaaS基座中的应用授权、能力开通与配额 |
| 订阅生命周期 | 管理试用、续费、升级、降级、到期与终止，明确生效时间及权益变化 |
| 交付与客户服务 | 提供订单、开通进度、订阅和使用额度查询，支持部署交付、升级与问题处理 |

支付成功与开通成功分别记录；重复通知不能重复授予权益，开通失败需支持重试与补偿。退款、到期或套餐变更时，按规则调整权限和配额，避免交易状态与实际可用能力不一致。

### 计量与计费

**使用事件 → 用量采集 → 校验去重 → 用量汇总 → 额度抵扣与计价 → 出账 → 对账与结算。**

| 方向 | 建设目标 |
| --- | --- |
| 计量对象 | 按产品选择模型输入与输出 Token、工具调用次数、知识处理量、存储量或服务时长等指标 |
| 用量归属 | 关联租户、应用、智能体、请求与计量时间，使明细可追溯到具体使用行为 |
| 采集与汇总 | 处理重复、延迟与失败事件，形成可核对的使用明细和周期汇总 |
| 额度管理 | 管理套餐内额度、用量包、有效期、余额和超额策略，提供额度预警与使用限制 |
| 计价规则 | 按产品支持固定订阅费、按量、阶梯及组合计价，区分免费额度、折扣与超额费用 |
| 账单与费用查询 | 展示计费周期、使用量、计价依据、抵扣和应付金额，支持明细核对与账单调整 |
| 对账与结算 | 核对订单、支付、用量、账单与退款，处理差异并形成结算记录 |

计量先记录实际使用，计费再按有效套餐与价格规则计算费用。明确失败调用是否收费、延迟事件归属周期、规则变更生效时间和重算方式；保留规则版本与调整记录，便于复核费用。

### 运营与经营分析

围绕租户、产品和套餐观察试用转化、开通成功率、续费、用量、收入与模型及工具成本，逐步支持客户服务、产品定价和资源投入决策。

### 规划交付顺序

1. **交易开通**：选定一个产品，走通订单、支付、订阅、开通与到期处理；覆盖重复通知、开通失败和退款场景。
2. **计量计费**：选定一个计量指标，走通明细采集、额度抵扣、计价与出账；能从账单追溯使用明细和规则版本。
3. **对账运营**：补齐续费与套餐变更、差异处理、结算及经营分析，形成可持续运营的产品交付路径。

具体领域边界、数据所有权与跨服务契约在实施前通过架构设计和 ADR 确认。
