# ADR-0004：逻辑删除唯一约束使用函数索引

## 状态

已接受（纳入 `java-domain-service 1.0.0`）

## 背景

领域表通常以 `delete_flag = 0` 表示有效记录。某些业务键只要求在有效记录中唯一，逻辑删除后应允许重新创建；另一些业务键出于审计、防冒用或历史归属要求，删除后仍需永久占位。

普通唯一索引 `UNIQUE (business_key, delete_flag)` 不能正确表达第一种语义：相同业务键只能分别存在一条有效记录和一条已删除记录，第二次删除并重新创建时会与已有的 `delete_flag = 1` 记录冲突。

## 决策

1. Java 领域服务的 MySQL 最低版本统一为 `8.0.13`。
2. 仅有效记录唯一、删除后允许重新创建时，使用函数唯一索引：

   ```sql
   ALTER TABLE `resource_api`
     ADD UNIQUE INDEX `uk_active_service_method_path` (
       `service_code`,
       `method`,
       `path`,
       (IF(`delete_flag` = 0, 0, NULL))
     );
   ```

3. 不得使用 `UNIQUE (..., delete_flag)` 表达“仅有效记录唯一”。
4. 删除后仍需永久占用业务键时，唯一索引不包含 `delete_flag`，并在领域设计中说明永久占位原因。
5. 普通查询索引可根据查询模式直接包含 `delete_flag`，不受函数唯一索引写法限制。

## 影响

- 有效记录把函数键映射为 `0`，数据库继续承担并发唯一性的最终防线。
- 已删除记录把函数键映射为 `NULL`，可保存多条历史记录并再次创建同一业务键。
- 本地、CI、测试和生产数据库都必须满足最低版本，不能只在某个环境支持函数索引。
- 已有表改造前必须检查重复有效数据、历史删除数据、在线 DDL 能力和回滚路径；初始化 SQL 与生产增量迁移仍应分离。

## 验证

迁移测试至少覆盖：首次插入成功、重复有效记录失败、逻辑删除后重建成功、多次删除并重建成功，以及不同租户或不同业务键互不冲突。
