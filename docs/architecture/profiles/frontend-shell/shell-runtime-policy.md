# 生命周期与跨应用契约

## 应用定义

`appKey` 是平台逻辑主键，`name` 是运行时名称，`entry` 是可加载入口，`activeRule` 是 Shell 路由契约。四者的来源、唯一性、缓存和失败处理必须可追踪。菜单数据可以提供定义，但进入运行时前必须校验。

## 生命周期

- 框架初始化必须早于任何子应用加载，且重复初始化幂等。
- 每个实例具有稳定 `instanceId`，挂载失败不得留下 DOM、监听器或缓存脏状态。
- 关闭 Tab、路由离开、重新登录和 Shell 卸载时必须定义 unmount/destroy 行为。
- 超时只能改善可诊断性，不能掩盖不可访问的 entry 或永久挂起的子应用。
- Shell 对同一应用的多实例能力必须验证名称隔离、状态隔离、样式隔离和路由隔离。

## 上下文与消息

- Shell 只传递子应用启动所需的最小上下文，例如 appKey、初始路由、Locale 和短期 Token 获取能力。
- 消息必须采用明确事件名、结构化 payload、时间戳和可选 requestId；协议升级需要兼容策略。
- 接收方校验消息来源、appKey、事件类型和 payload，不能信任任意 `window` 事件。
- 路由同步必须防止 Shell 与子应用相互回写形成循环。

## 联调验证

至少覆盖冷启动、首次挂载、重复打开、多实例、内部路由变化、Token 请求与失效、Locale 变化、关闭卸载、entry 不可用、深链刷新和重新登录。
