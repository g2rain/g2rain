# 过滤器链规范

## 顺序与依赖

- 请求级上下文必须先于读取或写入主体信息的过滤器建立。
- 请求体缓存必须先于日志、DPoP/签名和其他重复读取 body 的过滤器。
- 凭据认证先于 API 权限与可信主体透传。
- 请求完整性校验必须使用认证阶段确定的算法、密钥或摘要上下文。
- 主体透传只发生在全部适用入口校验通过后。
- 响应调整不得掩盖认证、权限、路由和下游业务错误。

项目在 `docs/architecture/runtime-flows.md` 记录实际过滤器、顺序值、前置依赖、跳过条件和错误行为。顺序变化视为协议变化，必须提供兼容性分析和回归测试。

## 认证分流

静态 API Key、JWT、DPoP 或其他方案必须由明确、无歧义的凭据判定分流。跳过不适用的认证过滤器不等于跳过路由匹配、API 权限、审计和下游授权。

## 白名单

白名单按最小范围配置，并区分全局与单过滤器豁免。新增路径必须说明业务原因、允许跳过的控制、剩余保护和负向测试；通配范围扩大需要安全评审。
