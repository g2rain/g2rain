# 项目脚手架与模板契约

`g2rain-app-cli` 是前端项目创建入口，`g2rain-app-template` 是模板实现。CLI 自身是 Node 工具，不采用 Frontend App 的浏览器分层；它的生成结果必须声明并符合本 Profile。

## 职责

- CLI：参数采集、模板选择、目标目录保护、复制排除、占位符替换、结果验证和错误报告。
- Template：生成项目的目录、依赖、运行时、生成器、配置、部署和项目文档。
- Generated App：业务需求、业务页面、项目偏差、资源配置和部署实例。
- Central Profile：跨 App 强制规则、版本与正式发布快照。

## 强制规则

1. 项目名、Context Path、模板路径和所有参数使用允许列表校验；最终目标必须保持在用户选择的父目录内。
2. 不覆盖已存在目标目录。需要恢复或覆盖时由用户明确处理，CLI 不递归删除不确定路径。
3. 外部 Git/进程命令使用参数数组 API，不拼接 shell 字符串。
4. 正式 CLI 版本使用可追踪模板 Ref/兼容映射，生成项目记录 CLI、模板 Ref 和 Profile 版本。
5. 模板提供机器可读 manifest，声明必需文件、占位符、Profile 版本和生成后验证命令。
6. 复制排除 `.git`、构建产物、依赖缓存、IDE 状态、密钥和本地/生产 Secret。
7. 交互与非交互模式共享校验和结果语义；自动化缺参时可预测失败，不无限等待 Prompt。
8. 模板/占位符变化同步 CLI 契约测试；不能用无边界全仓替换掩盖清单缺失。
9. 在临时目录完成复制、替换和验证后再原子移动到目标；失败不把半成品报告为成功。
10. 生成项目包含 `AGENTS.md`、`docs/project.yaml`、架构偏差和可执行构建命令，并声明采用的 frontend-app Profile。

## 版本与可复现性

CLI npm 版本、模板 Ref 和 Profile 版本是三个独立维度，必须建立兼容关系。相同 CLI 命令在相同输入和 Ref 下应生成可解释的同一基线；不能静默跟随模板默认分支让已发布 CLI 随时间改变行为。

是否复制模板 lockfile由模板发布策略明确：复制时生成项目可直接 `npm ci`；不复制时 CLI 必须提示 `npm install` 会重新解析依赖，并说明可复现性影响。

## 验证

至少覆盖：

- 两个命令入口、交互/非交互、默认值、取消、未知参数和非 TTY。
- 正常/非法项目名、路径逃逸、已有目录、Context Path 标准化。
- 本地模板、固定远程 Ref、网络失败、模板不完整和完整性失败。
- 复制排除、占位符完整性、特殊字符、重复执行和失败恢复。
- 生成项目 `package.json`、Profile 声明、残留占位符、依赖安装和 `npm run build`。
- npm tarball、bin shebang、干净环境执行和 CLI/模板/Profile 兼容组合。

## 安全

模板和 npm 包属于供应链边界。发布使用锁文件、最小 npm files、2FA/provenance、依赖扫描和可信 Git 来源；日志不输出 npm/Git Token。CLI 不自动执行模板脚本、安装依赖、创建远程仓库或部署，除非需求明确授权并设计完整失败恢复。
