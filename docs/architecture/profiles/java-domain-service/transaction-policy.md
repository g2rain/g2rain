# 事务与并发

## 事务边界

- 事务放在公开的 Service 用例或独立事务协作 Bean 上。
- 默认 Spring 代理模式下，不依赖同类内部调用触发 `@Transactional`。
- 一个领域不变量涉及的多次写入必须在同一事务中提交或回滚。
- 不为方便而把只读查询、外部网络调用和长耗时流程全部包入长事务。

## 冲突处理

如果并发唯一键冲突要求“失败写入全部回滚后再回查获胜记录”，异常必须先离开事务代理边界触发回滚，再由外层流程捕获和查询。不能在事务内部吞掉异常并继续提交可能的部分写入。

推荐结构：

```text
Resolver（非事务流程编排）
→ Creator Bean（事务内完成全部写入）
→ 冲突异常离开 Creator 并触发回滚
→ Resolver 捕获后回查
```

## 验证

Mock 单元测试不能证明 AOP 代理、数据库回滚和唯一键并发行为。涉及这些规则时必须提供使用真实事务管理器和数据库约束的集成测试。
