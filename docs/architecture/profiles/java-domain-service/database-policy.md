# 数据库与租户数据

- Java 领域服务统一以 MySQL `8.0.13` 为最低版本；采用函数索引的数据库实例、开发环境和 CI 不得低于该版本。
- 表、字段和索引来自明确领域语义，不把跨服务数据所有权隐藏在数据库关系中。
- 租户数据包含统一租户标识，并在查询、唯一键、写入和业务校验中保持一致。
- 绕过默认数据隔离只允许用于明确受信用例，Service 必须补足租户和访问校验。
- 唯一约束既保护数据完整性，也承担并发幂等的最后防线。
- 逻辑删除是否释放唯一值属于领域决策，必须通过设计或 ADR 明确。
- 仅有效记录需要保持业务唯一、逻辑删除后允许重新创建时，唯一索引必须使用函数键 `(IF(delete_flag = 0, 0, NULL))`，不得把 `delete_flag` 直接作为普通唯一键列。
- 已删除记录仍需永久占用业务唯一值时，唯一索引不包含 `delete_flag`，并在项目设计文档中说明原因。
- 普通查询索引可以按实际查询条件包含 `delete_flag`；上述函数索引规则只约束具有逻辑删除语义的唯一索引。
- 初始化建表脚本和生产增量迁移脚本职责分离；会删除数据的脚本不能用于已有数据环境。
- 结构变化必须说明历史数据、兼容性、执行顺序、验证和回滚。

## 仅有效记录唯一的标准写法

```sql
ALTER TABLE `resource_api`
  ADD UNIQUE INDEX `uk_active_service_method_path` (
    `service_code`,
    `method`,
    `path`,
    (IF(`delete_flag` = 0, 0, NULL))
  );
```

有效记录的函数键固定为 `0`，相同业务键会触发唯一冲突；已删除记录的函数键为 `NULL`，允许保留多条历史记录，也允许重新创建同一业务键。不要改写为 `UNIQUE (..., delete_flag)`：这种写法对同一业务键最多只能保留一条 `delete_flag = 1` 的记录，无法支持反复删除和重新创建。

具体决策和迁移要求见 [ADR-0004：逻辑删除唯一约束使用函数索引](../../decisions/0004-logical-delete-unique-indexes.md)。
