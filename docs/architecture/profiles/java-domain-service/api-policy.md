# API 与模块协作

## 默认协作模式

```text
同步查询：其他后端模块 → 领域服务 API 查询契约

交互编辑：App → Gateway → 数据所有者写用例

异步变化：其他模块发布领域事实 → 数据所有者幂等消费并更新
```

领域服务是自身数据的所有者，不能被其他模块当作远程数据库。同步依赖默认用于查询，不推荐发布 `save`、`update`、`delete` 等宽泛跨模块接口。

## 领域消息

- 消息表达已经发生的业务事实，不表达“修改某表某字段”的数据库指令。
- 消费者自主执行本领域校验和状态变化。
- 设计重复投递、乱序、重试、失败恢复、版本兼容和可观测性。
- 尚未实现消息消费者的项目必须明确标注规划状态，不能把推荐模式写成当前能力。

## 同步写入例外

只有具有强实时要求、明确受信调用方且不能合理使用 App 或消息的业务命令可以申请例外。例外必须记录到项目 `deviations.md`；长期影响多个项目时增加中央 ADR。
