# 知识服务与智能体集成

## 当前状态与职责

知识服务、运营端和 Agent 核心模块均已发布，当前提供知识对话与主应用演示。运行配置由责任项目维护。

| 2026-10-19 | 知识服务完成 v1.0.0 发布准备与服务端验证，知识运营端配套发布。 |

| 模块 | 职责 | 对外边界 |
| --- | --- | --- |
| 知识服务 | 文件与 FAQ、版本、审核、处理、发布、检索证据与回答接口 | 拥有知识数据、活动版本与处理状态 |
| 知识运营端 | 内容维护、审核发布与运营交互 | 经 Gateway 调用管理接口 |
| Agent Runtime | 对话与任务执行，组合模型、知识和工具 | 使用知识接口，不直接访问知识数据库、文件或向量索引 |
| IAM / Gateway / 领域服务 | 身份、入口权限与业务数据归属校验 | 分别执行认证、入口准入和领域授权 |
| 部署仓库 | 服务及 MySQL、文件、Docling、Milvus 等依赖的配置与编排 | 按环境配置持久化、网络和模型服务 |

MySQL 管理知识元数据和发布状态，Milvus 承担可重建的检索投影。组织与活动版本校验由知识服务执行，标签用于业务分类与筛选，不替代授权。

知识服务、运营端与 Agent 核心模块均已开发完成并发布；中央项目目录于 2026-11-04 更新为 completed。项目基线引用和架构偏差见[项目目录](catalog/projects.yaml)。

## 接入路径

1. 按知识服务版本文档配置存储、解析、向量索引与模型服务。
2. 通过运营端维护内容、审核、处理和发布知识版本。
3. 通过 `POST /knowledge/retrieve` 获取证据，或通过 `POST /knowledge/answer` 使用知识回答接口。
4. 智能体与业务调用方传递可信身份和组织上下文，按版本契约处理结果、引用、无证据和依赖失败。
5. 反馈进入运营修订流程，发布新版本后核对检索与回答变化。

完整状态机、字段、错误码、事务与恢复机制由知识服务版本文档维护，中央页不复制实现细节。

## 集成验证与运行维护

客服与 Agent 接入或升级时，执行以下验证：

- 核对正常召回、无证据、依赖超时与模型失败的结果和提示。
- 验证组织隔离、活动版本复核、原文下载与管理操作的权限边界。
- 使用至少两个租户、不同主体类型和不同业务数据归属，验证检索、会话、订单或业务工具调用不会跨租户读取或写入；越权请求应被拒绝并留下可追踪审计记录。
- 验证 Agent Runtime 只能通过知识服务契约取得证据，不能绕过 Gateway、领域服务或知识服务直接访问数据库、文件和向量索引。
- 验证发布、回滚、失败重试和索引恢复，并记录所用版本与环境。
- 核对引用来源、问题反馈和知识修订的对应关系。
- 记录数据库、文件、索引和配置的备份恢复方式。

客服场景的最小验收闭环为：**知识运营端维护并发布资料 → 知识服务按组织和活动版本返回证据 → Agent Runtime 组织模型与工具调用 → Chat Shell 返回回答与执行过程 → 业务服务继续执行租户、对象和数据权限校验**。
