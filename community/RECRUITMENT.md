# G2rain 开源共建招募：一起把 Agent 带进真实业务

我们正在寻找愿意一起打磨 **G2rain（谷雨）开源智能体平台**的伙伴。

如果你希望参与一个有实际业务模块、有前后端协作、也有模型与工具接入的开源项目，欢迎加入。你可以从一次问题复现、一处文档修正或一个小 PR 开始，逐步参与模块建设与维护。

## 我们正在做什么

G2rain 面向企业智能应用建设，连接模型、知识与业务工具，以 SaaS 基座和应用开发工具链支撑应用落地。现有业务模块均已开发完成并发布，覆盖组织身份与权限、知识库、Agent、模型访问、MCP 工具及业务管理界面。

接下来，我们希望和贡献者一起把这些能力打磨得更好用：让部署步骤更容易复现，让模型与工具接入更顺畅，让权限与任务执行更容易验证，让开发者能够沿着文档完成自己的第一个业务场景。

## 参与共建，你可以收获什么

**把技术兴趣变成可以展示的作品。** 从解决一个真实问题开始，你的代码、测试、文档与讨论都可以留下公开记录。无论是合入平台的 PR，还是独立发布的扩展，都能成为说明你如何分析问题、实现方案和验证结果的具体作品。

**在完整工程中积累实践。** G2rain 覆盖前端交互、Java 服务、身份权限、知识检索、Agent 执行、模型与工具接入。你可以沿着一个业务场景理解多个模块如何协作，积累接口设计、跨服务联调、部署排障与版本维护经验，也可以专注打磨其中一个方向。

**复用已有基础，更快验证自己的想法。** 开发新业务模块或应用时，可以按需复用组织、认证、权限、主壳、公共组件和研发工具，把更多时间投入自己的业务特点。主题、插件、Skill 和工具连接器也可以成为独立维护的开源项目。

**让你的项目被更多相关使用者看见。** 独立扩展公开后，可以向我们提交仓库地址和介绍。我们可以通过生态链接、文档导航和社区分享帮助推广，并注明作者与项目入口，让对这个方向有需求的人更容易找到你、试用项目并提供反馈。

**与关注同类问题的人一起交流。** 通过 Issue、方案讨论和 PR Review，你可以交换实现思路、获得反馈，并影响自己关心的功能和使用体验。也欢迎加入 G2rain 微信交流群，与维护者和其他参与者沟通，在项目上手、环境搭建、模块理解及贡献流程等方面获得指导。持续参与后，也欢迎与维护者讨论承担某个模块或方向的维护工作，具体职责与节奏共同商定。

你可以根据兴趣和可投入的时间选择参与方式。从一项小改进开始，逐步建立自己的实践与协作记录。

## 第一次可以做什么

以下是可讨论的切入点，具体任务以当前 Issue 和维护者沟通为准：

- 跟着一个组件的文档部署，记录遇到的缺失步骤、错误提示或配置歧义。
- 为一个已确认 Bug 补充最小复现和回归测试，再提交修复。
- 优化一个页面的空状态、加载状态、错误反馈或表单校验。
- 为一个 API、模型或 MCP 工具接入过程补充可运行示例。
- 选择一个业务流程，整理输入、权限、执行步骤和期望结果，帮助验证 Agent 行为。
- 修正过期链接、示例和版本说明，让下一位使用者少走一步弯路。

较大的功能、架构调整或跨仓库改动，请先讨论方案与范围，避免实现后才发现与现有职责重复。

## 基于 G2rain 扩展你的项目

除了参与现有仓库，也欢迎基于 G2rain 的基础能力开发自己的扩展，让不同团队的业务经验逐步形成可复用的生态：

- **新的业务模块**：围绕具体行业或业务领域，扩展服务、接口和管理能力。
- **新的应用**：开发业务子应用、主应用或面向特定场景的智能应用。
- **主题与界面扩展**：制作主题、布局、组件和交互方案，提供不同的产品风格。
- **插件与集成**：开发插件、MCP 工具、模型适配、Agent Skill 或外部系统连接能力。
- **部署与示例方案**：提供配套部署、行业示例和可复现的集成实践。

**扩展项目可以在你自己的 GitHub 仓库中发布和开源。** 你可以独立维护项目名称、版本与迭代节奏，按照所用组件及第三方依赖的许可证要求进行开发和分发。

项目公开后，欢迎通过 [Discussions](https://github.com/g2rain/g2rain/discussions) 或[项目邮箱](mailto:g2rain_developer@163.com)告知我们仓库地址。建议一并提供：

- 项目名称、简介和面向的业务场景。
- 公开仓库地址、开源许可证和当前版本。
- 适用的 G2rain 组件及版本，安装、配置和使用说明。
- 截图、演示或示例（如有），以及反馈问题的入口。

我们可以在确认项目介绍与链接后，将其添加到相关文档或生态导航，并通过社区渠道进行推广，帮助更多使用者发现你的项目。收录时会注明作者和独立维护的仓库地址，方便用户了解项目来源、版本兼容性和支持方式。

无论是一个主题、一个工具插件，还是一套完整业务应用，都欢迎分享。你也可以先交流扩展思路，与社区一起完善接口和集成方式。

## 如何加入

1. **了解项目**：体验演示，阅读目标仓库 README 与相关文档，选择你感兴趣的模块。
2. **说明意向**：在 [Discussions](https://github.com/g2rain/g2rain/discussions) 发起共建交流，或在相关 Issue 下说明希望参与的工作。
3. **确认一个小任务**：和维护者明确问题、范围、预期结果及验证方式，再开始实现。
4. **提交贡献**：按照[贡献指南](CONTRIBUTING.md)创建分支、执行验证并提交 PR。
5. **持续协作**：根据 Review 更新改动；有意长期参与的伙伴，可以进一步交流模块维护与后续规划。

介绍自己时，可以提供以下信息：

> 我希望参与的方向或仓库：  
> 我熟悉的技术，或希望学习的内容：  
> 我发现的问题或想做的一个小任务：  
> 我大致可以投入的时间与协作节奏：  
> 我的 GitHub 主页或相关实践（可选）：

不必提交完整简历，也无需公开私人联系方式。你可以直接通过 GitHub 讨论协作细节。

## PR 怎样提交

**统一流程：从上游 `develop` 创建工作分支 → 向上游 `develop` 提交 PR → Review 与修改 → 维护者验证 → 合并进入 `main` → 按计划发布。**

代码提交到对应组件仓库，平台介绍与治理文档提交到 `g2rain/g2rain`。一个 PR 聚焦一个问题，说明动机、实现内容、关联 Issue、实际验证结果，以及配置、数据库或跨组件兼容性影响。涉及页面交互时可附截图，涉及接口时请同步文档与必要测试。

贡献 PR 先进入 `develop`。我们完成测试环境验证及必要的跨组件联调后，再合并到 `main`。详细的 Fork、分支创建、推送及 PR 目标选择步骤见[贡献指南](CONTRIBUTING.md#3-提交-pull-requestpr流程)。

## 我们期待怎样协作

- 尊重彼此的时间，及时说明进展、疑问和阻碍；投入节奏可以提前沟通。
- 围绕问题与证据讨论，愿意阅读现有实现、接受 Review，也欢迎提出有依据的不同意见。
- 如实记录验证结果，对尚未覆盖的场景明确说明。
- 遵守[行为准则](CODE_OF_CONDUCT.md)，保护用户数据、凭据与其他敏感信息。

这是一份**开源社区共建邀请**。具体参与方式、投入安排及其他合作事项，以双方实际沟通为准；本文不构成雇佣或报酬承诺。贡献按目标仓库的许可证与贡献规范协作。
