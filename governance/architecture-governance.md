# 架构治理机制

## 职责

- 中央维护者：维护 Profile、组织级 ADR、版本和项目目录。
- 项目维护者：维护领域文档、架构例外、测试和基线升级。
- Agent：结合中央基线、项目声明、源码和 Git Diff 动态审核。
- Reviewer：确认架构问题、业务取舍和测试环境验收，不能把最终责任交给 Agent。

## 组织级变更

影响多个项目的模块、协作、数据所有权、安全或发布规则，先提出中央 ADR，再修改 Draft Profile 并选择代表项目试点。正式发布后由项目显式升级，不能静默改变所有仓库的有效规则。

## 项目例外

例外至少记录基线规则、偏离内容、原因、风险、安全和测试措施、负责人、复审条件。没有登记的偏离视为架构漂移。

## Review 输出

架构 Review 按严重程度给出文件、行号、证据、风险和建议，并区分确定问题与待确认事项。Review 默认只读；修复进入独立需求或缺陷流程。

## Git 流程

```text
feature/* 或 fix/* → develop → 测试环境验证 → main
```

中央基线和项目升级都使用 Pull Request。正式架构 Tag 只从已经评审的稳定内容发布。
